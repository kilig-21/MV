### 3.1 本轮新改的唯一一镜：v3-11

原写法 `eyes: blink(...) || 'dot'`：点状眼读不出方向，`look` 在这一镜等于没有，0.79 秒里角色是一张完全不变的脸
（城市全景里它只有 18u 高，换别的眼型又怕抢戏）。改法：

```js
const e  = face(t, [
  { t: 0.00, eyes: 'dot',    mouth: 'none', brow: null },
  { t: 0.46, eyes: 'normal', mouth: 'none', brow: null },
], 0.20);
const eb = withBlink(e, blink(t, { seed: 3130 }));
```

视线 0.34 先抬（比眼型早 3 帧），0.46 眼型才落成正常眼——一次「重新对上焦」，
同时把结尾接成 `normal`，与下一镜 `v3-12` 开头的 `normal` 连上，中间不跳。
实测抽帧见 `out/e4-transitions-v3-11.jpg`：0.26 / 0.36 / 0.46 三格渐进，没有一格是硬切。

## 4. 验证

### 4.1 抽帧拼表（每次表情变化前后各 3 帧，0.1 秒间隔）

16 个有角色的镜头 × 每个变化点 6 帧，共 26 段，全部渲染并 Read 过：

```
out/e4-transitions-v3-01.jpg  … e4-transitions-v3-19.jpg   （每镜一张，自动裁到角色）
out/e4-transitions-all.jpg                                  （全部拼一张，3640×2608）
```

- 判读结论：每一处都能看到**中间态**（半亮的眼白、半张的嘴、眉从 `null` 淡入），
  相邻两格之间没有「前一刻 A / 下一刻 B」的硬切。
- 已知的中间态瑕疵与 `report-expr-blend.md` 第 2 节一致：`normal ↔ shock/wide` 这类「从墨线眼型换成带眼白的眼型」
  的过渡里，0.18 秒占 4–5 帧，其中 1–2 帧是两种眼型半透明叠在一起（眼白偏灰）。
  在这一段的尺度（眼睛约 20–40px 宽）上读作「眼睛正在睁大」，不是一段灰糊；
  全段没有出现过 3 帧以上的灰。
- 0.1 秒的抽样间隔比 `ramp`（0.14–0.24 秒）粗，所以另外用 24fps 逐帧条（每帧 1/24 秒）补看了三处最猛的切换：
  `out/e4-24fps-strips.jpg`（v3-03 的 0.84、v3-09 的 1.36、v3-17 的 1.02，各 6 格）。
  逐帧看下来，每一格眼睛/嘴都在动，没有「前一刻 A / 下一刻 B」的两格。

## 5. 已知限制 / 留给下一轮

1. **`v3-04`、`v3-15`、`v3-18` 没有角色**，只有鸟、粉笔画、留声机。这一轮没有往这三镜里加角色——加了就是改构图。
   如果确实希望「全片 19 镜都有表情」，需要先在分镜层面决定给它们一个角色（那是新的构图决定，不是表情打磨）。
2. **v3-08 的外公**（绿，`u=17`）是画面右侧的次要角色，抽帧拼表按主角裁，外公的闭眼笑只在大图上确认过，
   没有单独的逐帧条。他在 1.66 之后就不再变化，风险低。
3. **v3-11 / v3-12** 的主角只有 18u 高，眼型变化在整幅画面里是「很小的一下」——
   这是刻意的：全景里它本来就应该是一粒，表情服务的是「它抬头了」，不是「它做了个表情」。
4. `blink()` 仍然是字符串快速路径，允许在渐变进行到一半时插进来（眨眼就是这个速度）。
   如果有哪一镜觉得眨眼把一次预备吃掉了，把该镜 `blink({ enabled })` 的窗口调开即可，不需要改过渡本身。
